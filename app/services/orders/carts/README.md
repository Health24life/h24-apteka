# Orders::Carts — API кошика

Кошик «Аптеки» для вебу й застосунку. Кошик — це замовлення в стані `cart`, прив'язане з першим товаром до однієї
аптеки й провайдера (модель — `Order`, `Order::Item`). Ціна й наявність **ніколи не зберігаються**: під час кожного показу й
кожної зміни сервіс звертається до провайдера в реальному часі через `Orders::Offers::Adapters` (для Pharmapoint — `Pharmapoint::Offers`,
`order/get-drugstore-for-order-goods`). Аптеку для першого товару фронт бере зі списку `POST /api/v1/goods/:id/drugstores`
(`Orders::Offers::Nearby`).

## Ендпоінти

Кошик — це замовлення в стані `cart`, тож маршрути — ресурс `orders`. Власник отримує доступ до кошика за `token` у шляху;
кошик акаунта відкривається лише із сесією його користувача — це вирішує `OrderPolicy`. Посилання для інших людей немає:
ділитися можна лише відправленою броню, щоб її забрали.

| Запит | Що робить |
|---|---|
| `POST /api/v1/orders` | Перший товар: `goods_id`, `drugstore_id`, `quantity`; створює кошик (`201`, `token`). Користувач, у якого кошик уже є, кладе товар у нього (`200`) |
| `GET /api/v1/orders/current` | Кошик користувача з сесією — звідси він бере `token` |
| `GET /api/v1/orders/:token` | Кошик із цінами в реальному часі; провайдер не відповів — `200` без цін, `prices_available: false` |
| `DELETE /api/v1/orders/:token` | `204`, кошик видалено з позиціями |
| `POST /api/v1/orders/:order_token/items` | Товар у кошик, лише для його аптеки; `drugstore_id` можна не передавати |
| `PATCH /api/v1/orders/:order_token/items/:id` | Нова кількість, перевірена в провайдера |
| `DELETE /api/v1/orders/:order_token/items/:id` | `204`; разом з останньою позицією видаляється й кошик |

## Потік

```
CartActions (owner: token зі шляху + сесія)
   │
   ▼
Find ── за токеном, якщо дозволяє OrderPolicy (гостьовий — будь-кому з токеном, акаунта — лише сесії його користувача);
   │    без токена — кошик
   │    користувача. Сесія відкриває гостьовий кошик, а в акаунта кошика немає → гостьовий переходить в акаунт
   │
   ▼
Opening / Tidy ── прихована аптека → кошик видалено, 404 cart_not_found + reason;
   │              прихований чи знятий SKU (або група) → позицію видалено, у відповіді в `removed`;
   │              вимкнений провайдер нічого не видаляє (може повернутися)
   ▼
Show ── in_drugstore про всі позиції → View (ItemView: available, price, total)
AddItem / ChangeQuantity ── зміна в пам'яті → Check (in_drugstore про весь кошик зі зміною) → save! → View
```

- **Перевірка** (`Check`) враховує лише SKU, що додається чи змінюється: в аптеці немає жодної упаковки —
  `goods_not_in_drugstore`, менше, ніж запитано, — `quantity_exceeds_stock` з `details.available_quantity` (навіть коли
  партнер позначив рядок непокритим). SKU, якого провайдер кошика не обслуговує, — `goods_not_in_drugstore` без
  звернення до провайдера. Немає даних (`order: null`) чи збій —
  `503 cart_check_unavailable`; ліміт — `503 cart_check_busy` + `Retry-After`. Нічого не зберігається, доки перевірка не
  пройшла; відповідь перевірки використовується для показу кошика після зміни, тож до провайдера звертаються один раз.
- **Позиція, якої зараз немає**, з кошика не видаляється: `available: false`, без ціни й без внеску в `total`.
- **Вимкнений провайдер**: кошик показується без цін (`prices_available: false`), до провайдера не звертаються; зміни —
  `503 cart_check_unavailable`, видалення позицій і очищення працюють.
- **Видалення** позиції чи кошика не прибирає непридатне (`Tidy`): позиція, що щойно стала непридатною, видаляється, як і
  запитано (`204`), а не `404`.
- **Перший товар користувача** у двох паралельних запитах: другий кладе товар у кошик, створений першим.
- **Кількість** — лише цілі упаковки (`invalid_quantity` ще до звернення до провайдера).
- **Помилки** — `Orders::Carts::Refused` (код, статус, деталі, `retry_after`), підклас спільного `Refused`, який
  `ApiController` перетворює на відповідь.

## Покинуті кошики

`Orders::Carts::AbandonedCleanupWorker` (cron `ORDERS_CART_CLEANUP_CRON`, за замовчуванням `40 4 * * *`; порожнє значення
вимикає) видаляє гостьові кошики без змін довше за `APTEKA_GUEST_CART_TTL_DAYS` днів (7). Кошики акаунтів і відправлені
замовлення не зачіпає. Час зміни кошика оновлюють позиції (`touch: true`).
