# Pharmapoint — клієнт партнерського API

Усе, що потрібно, щоб ходити в API Pharmapoint.ua: HTTP-клієнт, читачі відповідей, ліміти запитів, журнал звернень і розклад
фонових задач інтеграції. Сам імпорт каталогу, який користується клієнтом, лежить у [`catalog/sync`](../catalog/sync/README.md).

## Що де лежить

| Файл | Навіщо |
|---|---|
| `../pharmapoint.rb` | Простір імен і всі помилки інтеграції (`Error`, `ConfigurationError`, `TransientError`, `PermanentError`, `InvalidResponse`, `RateLimited`) |
| `config.rb` | Налаштування партнера (`dry-configurable`): з'єднання, ліміт, розмір сторінки груп, строки зберігання журналу. Пункти пошуку аптек — у `Catalog::Sync::Config` |
| `client.rb` | Клієнт: `dictionaries`, `category_tree`, `goods_groups`, `search_goods_groups`, `goods_group`, `drugstores`, `drugstore`, `offers_nearby`, `offers_in_drugstore`, `store_pick_up_order`, `order`, `order_history` |
| `transport.rb` | Одне звернення до партнера: ліміт, журнал, перевірка статусу й розбір JSON; запит із тілом надсилається методом `POST`, заголовки — з будь-яким |
| `search.rb` | Адаптер пошуку в реальному часі для [`Catalog::Search`](../catalog/search/README.md) |
| `bookings.rb` | Адаптер замовлень для `Orders::Bookings::Adapters`: створення самовивозу, статус за номером, пошук уже створеного в історії клієнта |
| `offers.rb` | Адаптер цін і залишків аптек у реальному часі для `Orders::Offers::Adapters`: аптеки поруч для SKU і одна аптека для позицій кошика, з ідентифікаторами каталогу |
| `readers/` | По читачу на оболонку відповіді; повертають прості значення з символьними ключами |
| `rate_limiter.rb` | Ліміт запитів, спільний для всіх воркерів (стан у Redis), і частки пошуку й кошика в ньому |
| `logging/middleware.rb`, `logging/request_logger.rb` | Запис кожної спроби запиту в журнал звернень |
| `logging/masker.rb` | Маскування ключа й телефону клієнта перед записом |
| `logging/display_masker.rb` | Маскування персональних даних клієнта під час показу журналу в адмінці |
| `logging/retention.rb` | Видалення прострочених записів журналу |
| `schedule.rb` | Розклад повторюваних задач для sidekiq-cron |

## Як користуватися

```ruby
client = Pharmapoint::Client.new(provider: Provider.find_by!(code: 'pharmapoint'), purpose: :refresh,
                                 user_id: current_user&.id, sync_run: run, attempt: 1)
client.goods_groups(page: 1)        # => Pharmapoint::Page з групами товарів
client.drugstore('38628')           # => запис однієї аптеки
```

- `search_goods_groups(query:, page:, location:, read_timeout:)` — пошук користувача в реальному часі: повертає сторінку груп і
  сирі записи груп для збереження без повторного запиту. Витрачає частку пошуку в ліміті й має власні короткі таймаути;
  `read_timeout` урізається до залишку часу звернення. Телефон клієнта не передається.
- `offers_nearby(goods:, location:)` і `offers_in_drugstore(goods:, drugstore_external_id:)` — `POST` на
  `order/get-drugstores-for-order-goods` (за координатами, лише аптеки з залишком: `with_empty_stock=0`) і
  `order/get-drugstore-for-order-goods` (одна аптека, також без залишку: `with_empty_stock=1`). Повертають аптеки з
  відстанню, годинами на сьогодні й позиціями: покрито, ціна в аптеці (`drugstore_price`; онлайн-ціна не читається),
  кількість. `order: null` — «даних немає», а не «товару немає» (`items` = `nil`). Витрачають частку кошика й мають
  власні короткі таймаути; телефон клієнта не передається. Адаптер зводить позиції кошика з тим самим SKU в один рядок.
  Партнер працює з цілими упаковками, і кошик приймає лише їх, тож частина упаковки в адаптері — помилка (`ArgumentError`), а
  не кількість, яку можна округлити.
- `store_pick_up_order(body)`, `order(number)`, `order_history(phone:)` — `POST order/store-pick-up-order`,
  `GET order/:order_number`, `GET order/history` (телефон клієнта — заголовком `Customer-Phone`, у журналі маскується).
  Без частки ліміту, з таймаутами `config.booking`; час партнера без таймзони читається як Київ.
- `purpose` — категорія звернення в журналі: `refresh` (оновлення даних), `search`, `offers` (ціни й
  залишки аптек у реальному часі), `booking`, `other`.
- `user_id` — користувач Health24, чия дія викликала звернення; для системних звернень (розклад) лишається порожнім.
- Помилки: `TransientError` (мережа, таймаут, 5xx) і `RateLimited` (429 або вичерпаний ліміт) варто повторити пізніше;
  `PermanentError` (інші 4xx) і `InvalidResponse` (200, але тіло не те) повтор не виправить.

## Налаштування

Усе — змінні середовища; заглушки прописані в `mise.toml`, справжні значення йдуть у `mise.local.toml`, не в `.env`.
Налаштування оголошені в `Pharmapoint::Config` (`dry-configurable`) з типовими значеннями й приведенням типу, а значення
зі змінних бере `config/initializers/settings.rb` у блоці `configure`: `ENV.fetch('ЗМІННА', поточне значення)`, тож
незадана змінна лишає типове значення. Порожня змінна для числа — помилка на старті; порожні ключ і домен означають
«не задано», порожня адреса — типову. Ініціалізатор будує конфіг після
кожного перезавантаження коду й заморожує його як `Pharmapoint.config`; спеки будують власний через `pharmapoint_config`.

| Змінна | Значення за замовчуванням | Що задає |
|---|---|---|
| `PHARMAPOINT_BASE_URL` | `https://pharmapoint.ua/api/v1/online-drugstore` | Адреса API |
| `PHARMAPOINT_API_KEY` | порожньо | Ключ. Без нього запит не йде, а прогін завершується статусом «помилка» |
| `PHARMAPOINT_DOMAIN_NAME` | `h24.ua` | Заголовок `Domain-Name` |
| `PHARMAPOINT_RATE_LIMIT_PER_MINUTE` | `60` | Власна межа запитів на хвилину на весь сервіс |
| `PHARMAPOINT_GOODS_GROUPS_PER_PAGE` | `50` | Розмір сторінки груп товарів |
| `PHARMAPOINT_SEARCH_RATE_LIMIT_PER_MINUTE` | `40` | Частка пошуку в ліміті: пошук перевіряє спершу її, потім спільний; відмова в частці не витрачає спільного бюджету, тож синхронізації лишається решта |
| `PHARMAPOINT_SEARCH_OPEN_TIMEOUT`, `PHARMAPOINT_SEARCH_READ_TIMEOUT` | `1`, `3` | Таймаути пошуку в секундах (можна дробові, напр. `0.5`), коротші за таймаути синхронізації |
| `PHARMAPOINT_SEARCH_PER_PAGE` | `20` | Розмір сторінки груп у пошуку |
| `PHARMAPOINT_CART_RATE_LIMIT_PER_MINUTE` | `15` | Частка запитів цін і залишків аптек (кошик і список аптек) у ліміті — так само, як частка пошуку |
| `PHARMAPOINT_CART_OPEN_TIMEOUT`, `PHARMAPOINT_CART_READ_TIMEOUT` | `1`, `3` | Таймаути цих звернень у секундах (можна дробові) |
| `PHARMAPOINT_BOOKING_OPEN_TIMEOUT`, `PHARMAPOINT_BOOKING_READ_TIMEOUT` | `1`, `10` | Таймаути створення й читання замовлень; частки ліміту немає, тож пошук і кошик не залишать бронь без бюджету |
| `PHARMAPOINT_DRUGSTORE_SEARCH_POINTS` | один пункт у Києві | JSON-масив об'єктів `{"latitude": градуси, "longitude": градуси, "radius": метри}`: навколо цих точок збирається довідник аптек. Читає `Catalog::Sync::Config`; формат і приклад — у [README синхронізації](../catalog/sync/README.md) |
| `PHARMAPOINT_LOG_RETENTION_<КАТЕГОРІЯ>_DAYS` | бронювання 14, пошук 1, ціни й залишки 1, оновлення даних 7, інші 7 | Строк зберігання журналу по категоріях |
| `SYNC_CRON_DICTIONARIES`, `SYNC_CRON_CATEGORIES`, `SYNC_CRON_GOODS_GROUPS`, `SYNC_CRON_DRUGSTORES` | див. `schedule.rb` | Cron кожного прогону; **порожнє значення вимикає задачу**. Прогін груп товарів за замовчуванням вимкнений |
| `LOG_CLEANUP_CRON` | `0 4 * * *` | Коли чистити журнал |

## Особливості контракту партнера

Партнер не публікує схему, а формат його відповідей нестабільний. Усе це гасять читачі, щоб імпортери про це не знали:

- оболонки різні (`data` об'єкт, масив, мапа; `data` + `meta`); `GET /drugstore/:id` віддає масив з одного елемента;
- ключ може бути відсутній замість `null`, об'єкт — порожнім масивом, число — рядком; відсутнє значення не є помилкою;
- ціна, залишок, ПДВ, передзамовлення, кількість аптек, відстань і графік «на сьогодні» читачі **відкидають на вході** — вони
  лишаються лише в живих запитах;
- поле `barcode` у картці — це код Моріон, а не штрихкод; назва береться з `name_uk`, інакше з `name` (`name_ru` не
  використовується).

## Журнал звернень

Кожна спроба запиту — окремий запис `Provider::RequestLog`: час, метод, шлях і параметри, заголовки й тіла (повні, `jsonb`),
код відповіді (окрема колонка, порожній без відповіді), **результат** (`success`, `http_error`, `timeout`,
`connection_error`, `invalid_response`), номер спроби, клас помилки, посилання на користувача й на прогін.

- Ключ і телефон клієнта в журнал не потрапляють (`Logging::Masker`): заголовки `API-Key`, `Customer-Phone`, `Authorization`,
  `Cookie` і поля `customer_phone_number` та `repayment_code` (код погашення е-рецепта) у тілах замінені маркером.
- Збій запису в журнал не ламає запит: його видно в `Rails.error`.
- В адмінці журнал («Синхронізація» → «Звернення до провайдерів») показує записи всіх категорій, але персональні дані
  клієнта маскує під час показу (`Logging::DisplayMasker`), не змінюючи збереженого: за полями договору замовлення (`customer_*`,
  `recipe_number`, `repayment_code`, `comment`, усе в `delivery` крім способу доставки, усе в `payment`) і за виглядом
  значення (телефон, e-mail, номер е-рецепта) в тілах, шляху, параметрах і заголовках. Вивантажень немає, фільтри — лише
  за метаданими (`Provider::RequestLog::FILTERABLE`).
- Прострочені записи видаляє `Pharmapoint::LogCleanupWorker` за строком категорії; нову категорію додають налаштуванням у
  `Config#log_retention_days`, інший строк задають змінною середовища.

## Тести

- Мережа в спеках заборонена (WebMock); відповіді — з `spec/fixtures/pharmapoint/*.json`.
- **Фікстури складені вручну за описом контракту в `docs/research/Pharmapoint_API_Data_Model.md`**, а не з живих відповідей:
  ключа й стенду партнера ще немає. Коли ключ з'явиться, їх треба перезаписати справжніми відповідями й виправити
  розбіжності у читачах.
- `goods_group_search_by_query.json` — відповідь `goods-group/search` із `query`, координатами й радіусом; теж складена
  вручну, справжньою відповіддю не підтверджена.
- `offers_nearby.json` і `offers_in_drugstore.json` — приклади з публічної Postman-колекції партнера, знеособлені й
  урізані; `offers_nearby_priced.json` — синтетична: у прикладі колекції за координатами `order` = `null` в усіх аптеках.
  У прикладі колекції за ідентифікатором аптеки ідентифікатор товару у відповіді не збігається з запитаним; адаптер
  зіставляє позиції за `goods_id`, а відповідь, де жодна позиція не збіглася, читає як «даних немає», а не «товару
  немає» — звірити зі справжньою відповіддю.
- Припущення, яке теж треба звірити: ключ передається заголовком `API-Key`, а ідентифікатор групи в `goods-group/get-by-id` — параметром `id`.
